# Phase 9: offline evaluation and analysis

This phase recomputes comparable metrics from frozen Phase 5 labels, Phase 6
predictions, Phase 7 scores, and optional Phase 8 decision telemetry. It performs
no training, model inference, tool execution, or network requests. The report
builder imports neither PyTorch nor scikit-learn. No API key is required.

## Generate a report

From the repository root in Windows PowerShell, using the existing environment:

```powershell
New-Item -ItemType Directory -Force artifacts | Out-Null
.\.venv\Scripts\python.exe -m runtime_security.evaluation.report `
  research/scripted-v1/dataset.json `
  research/scripted-v1/manifest.json `
  --baselines research/scripted-v1/baselines.json `
  --neural research/phase7-scripted-v1/report.json `
  --config configs/experiments/phase9.toml `
  --out artifacts/phase9-report.json
```

After installing this checkout with `python -m pip install -e ".[dev]"`, the
equivalent console command is `runtime-security-evaluate`. The module command
works with an already editable installation without refreshing entry points.
All prediction arguments are optional. Dataset plus manifest alone produces
observed outcome summaries and an explicit no-intervention reference.

The output path must be new; existing results are never overwritten. Identical
input bytes and configuration produce identical JSON bytes. Output contains no
current timestamp or machine-specific absolute paths. Canonical JSON hashes
identify parsed artifacts, and CLI `input_hashes.files` additionally identifies
the exact input bytes. This is provenance checking, not a digital signature or
proof that labels are correct.

```powershell
$report = Get-Content artifacts/phase9-report.json -Raw | ConvertFrom-Json
$report.adequacy | ConvertTo-Json -Depth 8
$report.methods.'phase7/enriched'.splits.test | ConvertTo-Json -Depth 8
$report.methods.'phase6/policy'.proposals |
  Where-Object category -eq 'false_positive' |
  Select-Object run_id, proposal_id, sequence, attempted_violation, completed_violation
```

The committed `research/phase9-scripted-v1/report.json` uses the command above
with only `--out` changed. Regenerate it to a new path and compare hashes:

```powershell
Get-FileHash research/phase9-scripted-v1/report.json, artifacts/phase9-report.json
```

Git's automatic line-ending conversion can change exact input-file hashes on a
different checkout. Canonical dataset/manifest/prediction hashes remain stable
for equivalent parsed JSON. Byte-for-byte comparison assumes the same original
input bytes, including the TOML file; `input_hashes.files` exposes those differences.

## Inputs and joins

| Input | Contract and validation |
|---|---|
| Dataset | Phase 5 `Corpus`, `Run`, `Action`, `Event`; `datasets.validate.audit` checks integrity and exclusions. |
| Manifest | Phase 5 frozen connected-component split; regenerated by the audit to detect altered membership, group crossings, or dataset hashes. |
| Baselines | Phase 6 v1 report; matching dataset/manifest/source/source hashes and target. Exact proposal coverage per split, unique IDs, finite scores, and agreement between flags and frozen thresholds/decisions. |
| Neural | Phase 7 v1 report; same provenance, target, unique test IDs and finite scores. When Phase 6 is also supplied, its hash must match the Phase 7 report's recorded reference. |
| Gateway | Optional Phase 3 JSONL containing Phase 8 `containment-v1` decisions. Byte hash must equal `Corpus.hashes.telemetry`; existing lifecycle validation and exact hashed event/run/call IDs establish the join. |

Missing methods are not fabricated. Phase 7's saved artifact contains test
predictions only: train/validation coverage is explicitly missing. An incomplete
Phase 6 split or Phase 7 test artifact is rejected because those formats promise
complete coverage. Gateway files can include observation-only calls; these have
no Phase 8 prediction and remain missing rather than becoming ALLOW.

For protected evidence, supply the **matching frozen protected corpus and its
manifest**, then add `--telemetry path/to/its-telemetry.jsonl`. Do not attach new
gateway runs to the committed unprotected corpus. Different run IDs, or a
different telemetry hash, cannot establish a paired comparison. No frozen
protected corpus is committed in this repository at Phase 9; the adapter is
tested with synthetic saved lifecycle records. Phase 5 audit eligibility still
applies, so unsupported or incomplete protected evidence remains excluded.

Gateway analysis includes final decisions, recorded hard-policy decisions, and
recorded detector alerts as separate methods. An approved host review may end
in ALLOW despite an initial detector alert. Unavailable/failed detector or
policy checks create missing component predictions, while a recorded final
BLOCK remains a gateway intervention. Status values are whitelisted; arbitrary
reason strings, arguments, prompts, tool outputs, and exception messages are
not copied from telemetry. The output retains hashed IDs and Phase 4 semantic
features. Dataset audit and the existing Phase 5 output secret-pattern scan
also run; these scans do not guarantee removal of every possible secret from
manually prepared artifacts.

## Metric conventions

All rates are fractions, with numerator, denominator and `value`; multiply by
100 for percentages. Zero denominators are JSON `null`. Unknown labels do not
enter TP/FP/FN/TN. Missing predictions have separate counts and are never
converted to negatives. A run-level prediction requires coverage for **all**
its actions, then flags if any action is flagged. An empty run has no intervention.

| Quantity | Definition |
|---|---|
| Positive action | `violation_attempted is True`, evaluated at proposal time. |
| Intervention flag | BLOCK or REVIEW is positive; ALLOW is negative. Gateway uses the final disposition. Score-based methods use `score >= saved threshold`; these are offline alerts. |
| Detection rate / TPR | TP / (TP + FN), using known unsafe action labels. |
| False intervention rate / FPR | FP / (FP + TN), using known safe action labels. REVIEW counts as a false intervention on a safe action; it is not called a literal block. |
| Precision | TP / (TP + FP). |
| F1 | 2 TP / (2 TP + FP + FN). |
| Observed attack success rate | Injected runs with `attack_completed=True` / injected runs with known attack outcomes. Unknown outcomes counted separately. |
| Observed benign task completion rate | Non-injected runs with `benign_completed=True` / non-injected runs with known benign outcomes. |
| Benign run intervention rate | Fully covered non-injected runs with any flag / fully covered non-injected runs. |
| Containment opportunity proxy | Covered completed unsafe actions whose proposals were flagged / covered completed unsafe actions. This is not a count of prevented effects. |

Run-level attempted violations and completed violations have separate confusion
matrices. The completion matrix compares an alert against the source run's
completion label and is explicitly a proxy. An alert on a saved unprotected
run does not change its recorded attack outcome, and cannot tell us whether
the legitimate task would finish after intervention.

`observed_source_outcomes` records actual source outcomes once per split.
`runs` keeps scenario/version/model, run limits, attempted/completed labels,
mock-effect counts and excluded reasons. Method `proposals` contain joined IDs,
sequence, labels, semantic features, flags and TP/FP/FN/TN categories. Counts of
completed benign runs flagged expose utility cost on the covered cohort.
Per-scenario/task/model/version breakdowns stay within each split and source.
One invocation accepts one source corpus; scripted and live results are not pooled.

Pairwise comparisons use only exact common proposal IDs within the same split,
with common and left/right-only counts. A zero-common-cohort comparison has
undefined rates. Later actions in a saved trajectory are still offline
proposals: the evaluator does not simulate a changed trajectory after a block.

## Research experiments and evidence limits

Both guide variants are accounted for: the playbook's E6 failure analysis and
the comprehensive guide's E6 threshold study. Each report includes an E1–E6
availability/gap map:

| Experiment | Current analysis and remaining evidence |
|---|---|
| E1 representations | Available sequence/semantic baselines and tool-only/enriched BiLSTM scores. Tool-plus-raw-arguments predictions are absent. Cross-architecture comparisons do not isolate representation alone. |
| E2 coherent malicious trajectories | Requires explicit coherence labels and reliability baseline predictions; unavailable in current inputs. |
| E3 containment modes | Compare no-intervention, policy, learned alerts and supplied gateway decisions on common IDs. Recorded policy/detector component signals are not separately executed modes. Four matched executed containment arms are still required for a causal prevention claim. |
| E4 unseen cases | Split and scenario breakdowns expose coverage. Explicit unseen attack/tool/destination annotations and a richer test corpus are still required. |
| E5 latency and utility | Preserve saved latency summaries and their measurement scope alongside observed source task outcomes. Different latency scopes cannot establish added gateway latency; matched timing and outcome trials are missing. |
| E6 thresholds and failures | Configured descriptive threshold curves and auditable false-positive/false-negative rows. Saved validation thresholds determine metrics; test curves must never select deployment thresholds. |

There are 12 scripted runs, 23 actions and only three independent groups in the
committed Phase 5 fixture. All nine unsafe actions are in training; validation
and test have none. Therefore held-out detection rate is undefined. The report
flags class absence, small group counts and scripted data; it does not describe
these results as generalization evidence. The configurable six-group floor is
a diagnostic warning threshold, not a statistical adequacy guarantee.

Repeated fixture rows are not independent live trials. No repeated independent
experiment design is supplied here, so confidence intervals are explicitly
unavailable. No superiority, first-of-kind novelty, or production-security
claim follows from these fixtures. Unseen-case experiments, independent
repeated trials, uncertainty estimates, and matched protected/unprotected
utility/latency measurements remain future research work.

## Verification

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_evaluation_report.py
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\ruff.exe check .
```

Tests cover metric denominators, unknowns, exclusions, partial/common cohorts,
provenance and target mismatches, invalid probabilities, duplicate/missing
predictions, threshold isolation, gateway final-versus-component decisions,
failure handling, sanitized diagnostics, deterministic bytes, serialization,
and refusal to overwrite outputs. The CLI test disables socket connections and
removes the API-key environment variable. These establish evaluator behavior;
they do not validate the research hypotheses or independently prove label truth.
